### Problem: Memory Usage Too High

**Symptoms**:
- Browser tab crashes
- Slow performance after running for a while
- Console warnings about memory

**Solution**:

```javascript
// Reduce memory footprint
const CONFIG = {
    WIDTH: 120,   // Reduce from 160
    HEIGHT: 68,   // Reduce from 90
    // ...
};

Memory calculation:

bytes = WIDTH × HEIGHT × STRIDE × 4 (Float32Array)
160×90×12×4 = 691KB (typical)
120×68×12×4 = 391KB (optimised)

Visual Artifacts

Problem: Flickering Shadows

Cause: Insufficient diffusion iterations or energy dissipation too high

Fix:

const CONFIG = {
    DISSIPATION: 0.98,  // Increase from 0.95 (retain more energy)
    // ...
};

Problem: Light Bleeding Through Walls

Cause: Surface continuity check threshold too lenient

Fix:

// In surface continuity check
const depthThreshold = 0.3;  // Reduce from 0.5
if (Math.abs(depth1 - depth2) < depthThreshold) {
    // Allow light transfer
}

Problem: Overly Bright or Dark Rendering

Cause: Exposure/tone mapping incorrect

Fix:

// Adjust exposure in rendering
const exposure = 1.2;  // Increase to brighten
const colour = Math.pow(rawColour * exposure, 1.0 / 2.2);  // Gamma correction

Common Errors

Error: "Cannot read property 'lattice' of undefined"

Cause: Attempting to access State.lattice before initialisation

Fix:

// Ensure bootSystem() is called first
window.addEventListener('load', () => {
    bootSystem();  // Allocates State.lattice
    requestAnimationFrame(mainLoop);
});

Error: "Maximum call stack size exceeded"

Cause: Infinite recursion in ray tracing or fluid propagation

Fix:

// Add depth limit to recursive functions
function trace(ro, rd, depth = 0) {
    if (depth > 5) return BLACK;  // Max 5 bounces
    // ...
}

Error: Canvas appears black

Diagnostic checklist:

  1. ✓ Canvas element exists in HTML
  2. ✓ Context acquired: ctx !== null
  3. ✓ State.lattice allocated
  4. ✓ Scene loaded: Scene.objects.length > 0
  5. ✓ Light source positioned correctly
  6. ✓ Rendering loop active

Frequently Asked Questions

Why fluid simulation instead of traditional ray tracing?

Traditional ray tracing:

  • ✅ Physically accurate
  • ❌ O(rays × bounces × samples) = expensive for soft shadows
  • ❌ Difficult to implement global illumination in real-time

Fluid-based approach:

  • ✅ O(pixels) = constant cost per frame
  • ✅ Natural soft shadows and colour bleeding
  • ✅ Emergent ambient occlusion
  • ❌ Less physically accurate (approximation)

Can this be GPU-accelerated?

Yes! The cellular automata structure maps naturally to compute shaders:

// WebGL compute shader pseudocode
#version 310 es
layout(local_size_x = 16, local_size_y = 16) in;

uniform sampler2D currentState;
layout(rgba32f) uniform image2D nextState;

void main() {
    ivec2 pos = ivec2(gl_GlobalInvocationID.xy);
    vec4 centre = texelFetch(currentState, pos, 0);
    vec4 left = texelFetch(currentState, pos + ivec2(-1, 0), 0);
    vec4 right = texelFetch(currentState, pos + ivec2(1, 0), 0);
    // ... diffusion/advection logic
    imageStore(nextState, pos, result);
}

Performance gain: 10-100× faster (depending on GPU)

How do I add more light sources?

// In Scene.objects array
Scene.objects = [
    {type: 'sphere', pos: {x: 0, y: 0, z: 0}, r: 1.0, emit: {r: 1, g: 1, b: 1}},
    {type: 'sphere', pos: {x: 2, y: 1, z: 0}, r: 0.5, emit: {r: 1, g: 0, b: 0}},  // Red light
    {type: 'sphere', pos: {x: -2, y: 1, z: 0}, r: 0.5, emit: {r: 0, g: 0, b: 1}}, // Blue light
];

Can I use this for 3D scenes?

The current implementation is 2D (screen-space simulation). For true 3D:

  1. Use 3D lattice: State.lattice = new Float32Array(WIDTH × HEIGHT × DEPTH × STRIDE)
  2. Extend ray marching to 3D space
  3. Add 6-directional (instead of 4) fluid propagation
  4. Warning: Memory and computation cost increases cubically!
