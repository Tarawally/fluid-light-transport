1 Introduction

In the domain of real-time computer graphics, we typically face a dichotomy: Ray Tracing offers precision but is computationally expensive for diffuse effects, whilst Rasterisation is fast but struggles with global illumination. This notebook explores a third way: treating light not merely as rays or radiant flux, but as a fluid substance that advects and diffuses across a surface topology.

This Hybrid Fluid-Light Transport engine leverages a novel pipeline:

  1. Injection: Stochastic Ray Tracing injects energy (photons) into the scene.
  2. Propagation: A Cellular Automata (CA) fluid solver propagates this energy as a viscous fluid.
  3. Rendering: The resulting state is tone-mapped and displayed.
NoteThe Fluid Analogy

In this model, Light Intensity is treated analogously to Fluid Pressure, and Light Flux is treated as Fluid Velocity. This allows us to use simplified Navier-Stokes equations to model light bleeding and soft shadows naturally.

2 System Architecture

The architecture is designed for performance, bypassing high-level abstractions in favour of specific memory layouts that maximise CPU cache locality.

2.1 Memory Layout: Structure of Arrays (SoA)

To achieve 60 FPS in a JavaScript-based environment without WebGL shaders, we must be judicious with memory. We avoid the overhead of JavaScript Objects for individual pixels. Instead, we employ a Structure of Arrays (SoA) layout within a single Float32Array.

Each pixel in the simulation grid is defined by a stride of specific floating-point values.

ImportantOptimisation

Using a single flat array allows us to process 200,000+ pixels efficiently by keeping related data contiguous in memory, reducing cache misses.

The memory offsets are defined as follows:

/**
 * Memory layout offsets for the Structure of Arrays (SoA).
 * Access a pixel's property by: index = (y * width + x) * STRIDE + OFFSET.
 * @enum {number}
 */
const FIELD = {
  R: 0,
  G: 1,
  B: 2, // Spectral Energy (Colour)
  VEL_X: 4,
  VEL_Y: 5, // Momentum Vector (Flow direction)
  ROUGHNESS: 6, // Surface material property (Friction)
  DEPTH: 7, // Distance from camera (Topology)
  OBJECT_ID: 11, // Discrete ID to prevent bleeding across distinct objects
  SLEEP_TIMER: 12, // Activity monitor for optimisation
};

const STRIDE = 14;

3.2 1D Propagation Visualisation

Below is a live simulation of the fluid solver logic running in this notebook. It simulates a 1D slice of the light transport.

Code 
function simulate1D(steps, disp, adv, diff) {
  const width = 100;
  // State arrays: [Energy, Velocity]
  let grid =  new Float32Array(width * 2).fill(0);
  let nextGrid = new Float32Array(width * 2).fill(0);

  // Initial Impulse (The "Light Source")
  grid[20 * 2] = 2.0; // Energy
  grid[20 * 2 + 1] = 1.0; // Initial Velocity

  let history = [];

  for(let t=0; t<steps; t++) {
    for(let x=0; x<width; x++) {
      const idx = x * 2;
      let energy = grid[idx];
      let velocity = grid[idx+1];

      if(energy < 0.01 && Math.abs(velocity) < 0.01) continue;

      // 1. Advection (Transport)
      // Light carries momentum, pushing it forward
      let thrust = velocity * adv;
      let targetX = Math.min(width-1, Math.max(0, Math.round(x + thrust)));
      let targetIdx = targetX * 2;

      // 2. Diffusion (Scattering)
      let remain = energy * (1-diff);
      let spread = energy * diff;

      // Update Next State with Dissipation
      nextGrid[targetIdx] += remain * disp;
      if(targetX+1 < width) nextGrid[(targetX+1)*2] += (spread/2) * disp;
      if(targetX-1 >= 0)    nextGrid[(targetX-1)*2] += (spread/2) * disp;

      // Decay Velocity (Viscosity)
      nextGrid[targetIdx+1] += velocity * 0.9;
    }

    // Ping-pong buffers
    for(let i=0; i<width*2; i++) {
        grid[i] = nextGrid[i];
        nextGrid[i] = 0;
    }

    // Store history for visualisation (just energy)
    let row = new Float32Array(width);
    for(let i=0; i<width; i++) row[i] = grid[i*2];
    history.push(Array.from(row));
  }
  return history;
}

As illustrated above, light does not merely stop at a surface; it flows around it. The Advection parameter controls how much the light’s momentum carries it forward (creating directional shadows), whilst Diffusion controls how much it scatters into the surroundings (creating ambient occlusion).
